# Android bootstrap API contract

## Endpoint

`GET https://paneldomain.com/panel/api/v1/bootstrap`

The hostname is a development placeholder. Production must use the real domain and HTTPS.

The endpoint is public and read-only. It does not accept Xtream usernames or passwords. Responses set `Cache-Control: no-store` so intermediary caches do not serve stale panel data.

## Example response

```json
{
  "installation_id": "a2c43862-3d18-4c51-a4a5-4c9c0f9c2c22",
  "config_updated_at": "2026-11-08T18:00:00Z",
  "checksum": "sha256-hex-digest",
  "servers": [
    {
      "id": "9dc8a2f3-8aac-491e-8b53-4ae917cfa49c",
      "name": "Provider One",
      "base_url": "https://provider.example:8080",
      "enabled": true,
      "sort_order": 10,
      "updated_at": "2026-11-08T17:55:00Z"
    }
  ],
  "maintenance_messages": [
    {
      "id": "1c2fc2b6-e9ef-44e5-a902-4708bb75e32a",
      "title": "Scheduled maintenance",
      "body": "Some services may be temporarily unavailable.",
      "type": "warning",
      "server_id": null,
      "starts_at": "2026-11-08T18:00:00Z",
      "ends_at": "2026-11-08T20:00:00Z"
    }
  ]
}
```

The example IDs and provider are illustrative only.

## Field semantics

- `installation_id`: random UUID created with the panel metadata row. It survives ordinary configuration edits and a database restore. A genuinely fresh database creates a new value.
- `config_updated_at`: UTC timestamp touched after every server or maintenance message mutation, including deletion. This is diagnostic/change metadata, not the only change detector.
- `checksum`: SHA-256 generated by the panel from the response configuration fields excluding `checksum`. The app stores and compares this opaque value with its previously stored value; it does not need to re-create PHP's JSON serialisation to compare it. It detects content changes including scheduled messages becoming active. HTTPS protects the response in transit.
- `servers`: complete server inventory, including disabled records. `id` is stable if the admin edits a provider name or base URL. Deleted records disappear from the list.
- `base_url`: full provider root URL, including scheme and optional port, with trailing slash removed.
- `maintenance_messages`: messages active at the time of the request. `server_id: null` means show globally; otherwise target only the matching server UUID.

## Android sync rules

1. Request on every cold app launch, and after a prolonged background interval.
2. Validate HTTPS, response shape, UUIDs, URLs, timestamps and checksum before changing local state.
3. If `installation_id` is different, force a full replacement even if the timestamp looks older or the checksum happens to match.
4. If installation ID is unchanged but checksum differs, update the local cache.
5. Apply the new server list in one database transaction. Do not partially apply a failed download.
6. Keep credentials keyed by server UUID. A panel edit to `base_url` must not clear the saved username/password.
7. If a server is disabled or deleted, do not allow a new connection to it. Existing credential records may be retained briefly for recovery, but must not be used until the server is re-enabled/present again.
8. If the panel is unreachable, keep the last valid cache, clearly indicate it may be stale, and offer retry. Do not clear credentials.

## Provider check

The Android app performs provider availability/authentication checks directly from the device using the selected provider's Xtream API and the user's own credentials. The panel must never receive those credentials. Avoid logging request URLs because common Xtream endpoints carry the username and password as query parameters. Distinguish network/time-out failures from an explicit authentication failure.

A provider using plain HTTP cannot protect credentials in transit. The app should warn when a configured provider URL is not HTTPS; whether to allow that connection is an Android product decision to settle during integration.
